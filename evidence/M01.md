## Rule and scenario coverage

Seven symbolic rule IDs are reached by literal model scenarios across count=0 and count=2. They are not all reachable in each individual configuration. Runtime witness IDs `M01-RX-01` through `M01-RX-11` are embedded in the canonical rules and emitted into the generated obligation document.

The bounded comparison domain is n=0..4; all {a,b} value words of length 0..4; and complete/error/cancel endings. This gives 5 × 31 × 3 = 465 scenarios. Each compares notification content/time and source acquisition/release. Other tests cover empty and one-value boundaries, error identity, hot-input subscription independence, cooperative synchronous cancellation and late attempts after unsubscription.

## Limits

No arbitrary RxJS effect interpreter, timed/higher-order/shared operator model, JSON execution loader, generic JSON Schema validator, proof-assistant development, arbitrary reentrant trace model, or full catalogue is shipped in M01. Human descriptions co-located with functions are reviewed annotations, not generated semantic proofs. Structural checks do not decide universal symbolic guard completeness.

The next checkpoint is M02: additional reference operators, beginning with map and filter, while retaining this baseline and explicitly extending the schema when new behavior requires it.
